06 / Test

Regression-test before you promote.

1 / FIXED CASES

Same inputs

Normal, edge, injection and PII cases.

→

2 / EXPECTATIONS

Checks per case

Must contain, must not contain, length, schema.

→

3 / COMPARE

Baseline versus candidate

Run both; any case that got worse is a regression.

→

4 / DECIDE

Promote or stop

Fewer passes than baseline means do not promote.

Test the actual approved rubric and dataset, not a fresh one each time.

07 / Conversation context

Memory is just what you send.

HISTORY

Messages list

Converse takes alternating user and assistant messages. The model remembers only what you include.

STORE

Persist it

Keep turns in DynamoDB keyed by session, so any Lambda can rebuild the context.

TRIM

Budget tokens

Cap the window: drop old turns or replace them with a short summary.

Longer history means more tokens on every call and a higher chance of hitting the limit.

08 / Control plane

When the workflow needs a control plane.

STEP FUNCTIONS

Durable orchestration

Parallel for two analyses, Choice for the risk threshold, Retry for transient tool failures, and an execution history to audit.

BEDROCK FLOWS

Prompt composition

Prompt chaining, model calls and conditional GenAI steps, built visually and versioned. Not the pick when operations need state-machine controls.

TRACES AND LOGS

Debugging, not orchestration

Agent traces and router logs show behaviour. They give no durable state, retry policy or managed audit path.

Lambda tasks inside the state machine call Bedrock, an agent alias, or a Strands runtime.

Amazon Bedrock · Prompt engineering and governance

10 / 11

AWS Step Functions is the best fit when an AI workflow needs durable orchestration, parallel branches, conditions, retries and execution history. Use a Parallel state for the two analyses, a Choice state for the risk threshold, and Retry rules for transient tool failures. Choose Standard workflows for long-running, auditable work: they show execution history, run exactly once, and can last up to a year; Express workflows are for high-rate work of up to five minutes, with history sent to CloudWatch Logs. Retry defaults are IntervalSeconds 1, MaxAttempts 3, BackoffRate 2.0 and JitterStrategy NONE; Retry and Catch apply to Task, Parallel and Map states, and a Parallel state fails as a whole if any branch fails. Amazon Bedrock and agent frameworks still matter: Lambda tasks can call Bedrock APIs, invoke a Bedrock agent alias, or call a Strands-based agent runtime, and Step Functions provides the control plane around those calls. Step Functions also has optimized integrations for the Bedrock InvokeModel and CreateModelCustomizationJob APIs. Bedrock Flows is stronger for prompt chaining, model calls and conditional GenAI composition; the AWS Flows page gives no use-Flows-when rule, so the boundary with Step Functions is design judgment. Agent traces and custom router logs help developers understand agent behavior but do not replace a managed workflow service when the scenario depends on durable state, retry policies and auditable execution paths. See the Supporting services page in the study site for the full comparison.
