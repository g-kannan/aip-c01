02 / Backoff

Wait longer, and randomly.

# full jitter
cap = 20
base = 0.5
wait = random(0, min(cap, base * 2**attempt))
# bound the whole call
max_attempts = 4
deadline = 5 # seconds in total

SDK

Retry modes

The AWS SDK offers legacy, standard and adaptive retry modes. Standard backs off with jitter.

BUDGET

Cap both

Limit attempts and total time. Retries multiply latency.

03 / 10

Do not stack your own retry loop on top of the SDK's without a budget. Adaptive mode adds client-side rate limiting based on throttling responses. Set a bounded timeout and retry budget so a slow dependency cannot hold your Lambda or your user for minutes.

03 / Thundering herd

Do not retry in lockstep.

PROBLEM

Same wait, same moment

Many clients throttled together all retry together, and throttle together again.

FIX

Add jitter

Random waits spread retries over time, so the service recovers sooner.

PROOF

Watch the chart

In the simulator, compare exponential with full jitter: spikes versus a smooth tail.

Backoff alone is not enough. Jitter is what breaks the synchronization.

04 / Circuit breaker

Stop calling a dependency that is down.

CLOSED

Normal

Calls go through. Count consecutive failures.

→

OPEN

Fail fast

After N failures, skip calls for a cool-down. No latency, no cost.

→

HALF-OPEN

Trial call

After the cool-down allow one call. Success closes it; failure reopens it.

Fail fast protects the dependency and your users' wait time.

A circuit breaker is per dependency, for example per model or per tool. It complements retries: retries handle brief blips, the breaker handles sustained outages.

3 / DEGRADE

Friendly error

07 / Streaming

Retry before the first visible chunk.

BEFORE

Safe to retry

If the stream fails before any text reached the user, retry or fail over quietly.

AFTER

Not safe

Once text is visible, a retry would duplicate it. Show an error or let the user resume.

OBSERVE

Time to first token

Track it separately from total latency: it is what users feel.

Retry stream errors inside the server (for example in Lambda) before forwarding content. After forwarding, treat the failure as final for that response. ConverseStream sends the usage metadata at the end, so token counts arrive last.

08 / Agents

Every loop needs an exit.

Stopping conditions

  • Maximum steps
  • Time budget
  • Token or cost budget
  • Repeated-action detection

Boundaries

  • Least-privilege role per tool
  • Validate tool inputs; handle tool errors
  • Human approval for risky actions
  • Circuit breaker on flaky tools
