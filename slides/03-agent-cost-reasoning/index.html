AGENTCOST01 · Reasoning and execution cost

01 / 12

Frame the talk: this is the first of the cost questions in the Agentic AI Lens. It is about the tokens an agent burns while it reasons and while several agents coordinate, not about which model is called. Model choice and prompt size are the next deck (AGENTCOST02).

01 / The question

Cost grows in the loop, not the prompt.

REASONING

Loops repeat

Plan, execute, verify and reflect cycles each consume tokens, and nothing stops them unless you add an exit.

COORDINATION

Agents multiply it

Every handoff and every supervisor layer adds inference calls on top of the real work.

OUTCOME

Predictable budgets

Design cost-aware reasoning up front and avoid the cost growth that appears after launch.

Goal: expensive model calls only where language understanding is needed, and everything else bounded, shared or rule-based.

AGENTCOST01 · Reasoning and execution cost

02 / 12

The Lens says teams that design cost-aware reasoning patterns early can reach predictable token budgets, and avoid the cost growth that tends to emerge once an agentic project is live. The capability intent has five parts: bounded reasoning cycles, coordination that scales with task complexity rather than conversation length, orchestration matched to how deterministic each decision is, hierarchies as shallow as the workflow allows, and reasoning and coordination cost tracked as separate metrics.

BP01 / Reflection loops

Every loop needs an exit.

  • Set three limits per agent: a maximum iteration count, a confidence threshold and a per-session token budget.
  • Reflect selectively. Run full self-correction only when the first output scores below a threshold.
  • Track tokens per cycle and decision quality, then tune the limits from data.

Gate

Enforce caps in AgentCore Policy, not just the system prompt. A prompt-only cap can drift under prompt injection.

AGENTCOST01 · Reasoning and execution cost

04 / 12

Each reflection loop assumes another iteration improves the answer by more than it costs. Make the loop emit a structured confidence signal with every action, inspect it in the orchestration layer, and stop when it clears the threshold. Iteration caps written only in the system prompt can drift under adversarial input, so enforce them at the traffic layer using Cedar policies in Amazon Bedrock AgentCore Policy at the AgentCore Gateway boundary. AgentCore Runtime gives each session its own budget. Use smaller models for the plan and verify phases and keep the largest model for execution.

05 / 12

The five implementation steps from the Lens. One: set termination conditions per agent and enforce them with AgentCore Policy Cedar policies at the Gateway. Two: enable AgentCore Observability to capture per-session token counts through OpenTelemetry and put CloudWatch alarms on anomalous per-cycle patterns. Three: use AgentCore Evaluations with LLM-as-a-Judge so early-termination thresholds rest on measured quality. Four: score each initial output with a lightweight rubric and reflect only below a configurable threshold. Five: review cost-quality baselines monthly, or quarterly for stable workloads, and adjust thresholds, iteration limits and reflection triggers.

BP02 / Handoffs

Send a summary, not the transcript.

ANTI-PATTERN

Full history, every handoff

Shared facts are re-sent to each agent, so context grows with agent count. Handoff cost goes untracked.

PATTERN

Structured handoff + shared memory

A versioned summary: task spec, relevant facts, constraints. Common context lives in AgentCore Memory, written once and read by many.

Rated High: redundant context at every handoff is the largest hidden cost in a multi-agent system.

AGENTCOST01 · Reasoning and execution cost

06 / 12

Treat handoff messages as structured summaries. Version the schema so receivers can reject malformed handoffs. AgentCore Memory supports write once, read many: one agent stores a fact under a session ID and actor ID, and collaborators read it without re-embedding it. A small model call or a Lambda function can distill context to the minimum sufficient set before each handoff. Document which agent owns writes to each memory namespace. The outcome is coordination cost that tracks task complexity rather than conversation length or agent count.

BP02 / Flatten and measure

Flatten the tree, then watch the ratio.

  1. Distill context with a small model or Lambda before each handoff.
  2. Audit supervisor-worker depth. Replace middle layers with direct worker-to-worker calls over the AgentCore Runtime A2A protocol.
  3. Publish agents as tools through AgentCore Gateway with Semantic Tool Selection on.
  4. Run AgentCore Evaluations on live tool-call traces and in CI/CD.
  5. Tag every call with workflow-id and agent-role. Alert in AWS Budgets above the ratio.

07 / 12

Each supervisor-worker layer adds at least one inference to delegate and one to synthesize, so hierarchies deeper than three levels compound fast. The diagnostic metric is the orchestration-to-execution token ratio, and supervisors should use no more than 20 percent of total workflow tokens. AgentCore Observability gives distributed tracing so agent-to-agent cost shows as its own category. The full step list in the Lens also includes designing structured handoff messages and provisioning shared memory with ownership rules, which are on the previous slide.

AGENTCOST01 · Reasoning and execution cost

08 / 12

At each orchestration point, the routing decision is either a selection among a finite set of conditions, such as task type, output classification or error code, which rules can handle, or an open-ended judgment that needs a model. Teams often pay for AI supervision across a whole workflow simply because the pattern defaults that way. The quantitative guidance in the Lens is rules for fewer than ten deterministic branches, a lightweight classifier for ten to fifty categories, and an AI supervisor only for unbounded category spaces. The classifier can be a small Bedrock model or a rule-based heuristic, and its escalation rate is the tuning signal.

BP04 / Hierarchies

Compact manifests, autonomous workers.

  • Describe each worker as a structured manifest: description, input schema, output schema.
  • Let supervisors discover tools at runtime through Gateway MCP, not a long prompt.
  • Workers finish sub-tasks end to end and return one result with a confidence score.
  • Workers read shared context from AgentCore Memory. Context relayed through a supervisor is sent twice.

AGENTCOST01 · Reasoning and execution cost

10 / 12

Supervisor cost is driven by how expensive each routing decision is, which manifest size controls, and by how often routing happens, which autonomy controls. AgentCore Policy through Gateway limits which tools each worker can invoke on its own. Plan-then-execute can compress repeatable workflows further. The 15 percent figure is the example target in the Lens: alert when supervisor tokens exceed 15 percent of worker tokens. The anti-patterns are verbose natural-language capability descriptions, which make cost grow linearly with worker count, and supervisor check-ins after every sub-step.

Watch for these

BP01

Open loops

No iteration or cost caps. Reflection on every output. Fixed counts instead of confidence.

Default AI routing

BP04

Verbose manifests

Prose capability descriptions. Supervisor check-ins after every sub-step.

Common thread: tracking only the aggregate workflow cost hides these.
