01 / Exam decision

Pick the inference API.

Converse ↗

Use for a complete response with a consistent message interface across supported models.

Chat, summarization, classification

ConverseStream ↗

Use for incremental output in interactive apps. Process events and assemble content.

Streaming support is model dependent

InvokeModel ↗

Use a model-specific payload for embeddings, image generation or native features outside Converse.

Native streaming: InvokeModelWithResponseStream

Converse parameters ↗

modelId: model or profile · messages: role + content · inferenceConfig: maxTokens, temperature, topP · additionalModelRequestFields: model-specific options

Exam trap: Conversation history is managed by the application and sent on later turns. Converse uses bedrock:InvokeModel; streaming uses bedrock:InvokeModelWithResponseStream.

02 / Exam decision

Choose the routing boundary ↗

In-region

Use a supported model in one Region when the workload requires processing there.

Resource: model ID or ARN

Geographic ↗

Bedrock routes to eligible Regions within the profile’s geography, such as US or EU.

Choose for a geographic boundary

Global ↗

Bedrock can route across supported commercial Regions worldwide.

Choose only if worldwide processing is allowed

Inference profile ↗

Pass the supported profile ID or ARN in modelId to Converse, ConverseStream or InvokeModel. An application profile can track costs and usage; it may be regional or cross-region.

Exam traps: Check model and source-Region support, destination restrictions, IAM and SCPs. A blocked destination can cause a geographic profile request to fail. Cross-region routing does not guarantee lower latency.
