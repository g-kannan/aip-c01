Query expansion: an approved synonym list maps internal acronyms to formal terms before retrieval. Decomposition splits a multi-part question into sub-queries. Reranking improves order, not recall. If chunks are wrong, no later step rescues them.

06 / Search settings

Hybrid finds the ID. Rerank fixes the order.

OptionUse it whenWatch for
HYBRIDUsers ask natural-language questions that also contain exact identifiers, such as alarm E42.Needs a filterable text field. Supported for OpenSearch Serverless, Amazon RDS and MongoDB; on any other store it silently runs as semantic.
SEMANTICQuestions are paraphrased and meaning matters more than the exact words.An exact identifier can be outranked by passages that only sound similar.
RerankingThe right passage is retrieved but ranked too low.Overrides the default ranking and works on text only. Cohere Rerank 3.5 or Amazon Rerank 1.0; Amazon Rerank is not in us‑east‑1. It cannot add passages that were never retrieved.
Direct OpenSearchThe app is not tied to the Knowledge Bases API.You own the hybrid query and the pipeline that combines scores.
Staying on the Knowledge Bases API? HYBRID plus a reranker is the lower-code fit.

08 / 11

In a customer-managed Knowledge Base, vectorSearchConfiguration.overrideSearchType takes HYBRID or SEMANTIC. HYBRID queries both the vector embeddings and the raw text, so it suits natural-language questions that also include exact identifiers. The AWS page says hybrid search is only supported for Amazon RDS, OpenSearch Serverless and MongoDB vector stores that contain a filterable text field; otherwise the query uses semantic search, with no error, so test it. Reranking can be used through Retrieve or RetrieveAndGenerate, works only on textual data, and its results override the default Knowledge Bases ranking. The supported reranking models are Amazon Rerank 1.0 and Cohere Rerank 3.5, and Amazon Rerank 1.0 is not available in US East (N. Virginia). A reranker orders what retrieval returned; it cannot rescue a passage that was never retrieved. Calling OpenSearch Serverless directly is valid in another architecture, using a hybrid query and a search pipeline that combines scores, but if the application must keep using the Knowledge Bases API, the retrieval configuration is the lower-code fit. The AWS pages read do not say whether hybrid search and reranking can be combined in one call, and the direct OpenSearch point was not checked against its documentation, so verify both. The Knowledge Base Lab in app.py has the SEMANTIC and HYBRID selector; it does not yet send a reranking model for vector-store knowledge bases.

07 / Keep it fresh

Sync the index when sources change.

1 / DETECT

A source changes

S3 event, schedule, or a pipeline step after a document update.

→

2 / SYNC

Start an ingestion job

The job adds, updates and removes only what changed.

→

3 / VERIFY

Check the result

Failed documents, counts, and a canary query for a known fact.

Deleting a source file does nothing until the next sync: stale answers come from stale indexes.
